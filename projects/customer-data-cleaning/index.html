04 / Methodology

Keep the source. Make each rule explicit.

  1. STEP 01

    Inspect and preserve

    Keep the original 500-row CSV separate. Identify blanks, repeated IDs and the generator's source conventions.

  2. STEP 02

    Normalize known fields

    Trim whitespace, normalize names and email casing, format phones, map city variants, and parse dates under the known conventions.

  3. STEP 03

    Retain one row per ID

    Keep the first observed source row for each Customer_ID. Exclude later rows without summing their Total_Spent values.

  4. STEP 04

    Log and reconcile

    Leave uncertain fields blank, record the original CSV row number, and reconcile the clean export, queue, dashboard and workbook.

Date policy and its limits

The generator uses YYYY-MM-DD, DD-MM-YYYY and MM/DD/YYYY. Its literal 03/04/2026 marker is quarantined. Other slash dates follow the generator's known MM/DD convention, including values that would be ambiguous without that context. This rule is specific to this exercise; a production import must confirm the source locale before parsing.

05 / Quality control

Reconcile the handoff,
then explain the gaps.

  • Reproduce all 470 cleaned rows and all 77 queue entries from the untouched source.
  • Confirm 500 − 30 = 470 and verify one row per Customer_ID.
  • Match workbook clean data, review queue, 60-row source sample, dashboard counts and city totals to the CSVs.
  • Check retained date order and duplicate spend conflicts. Neither check found a conflict in this dataset.

What still needs human review

Missing contacts and the six quarantined dates stay unresolved. Duplicate exclusions are audit events, not pending blank fields. First-observed-row retention is reproducible for this generated source; a real system may require a verified timestamp or source-priority rule.

The original workbook is a static snapshot with no formulas. Its matching totals do not imply that it refreshes when someone changes a cell. Names repeat across IDs, so name alone is not a reliable key.

Lessons learned

Define the counting unit before building a dashboard. State the date convention. Keep formatting separate from verification, and preserve the source row reference when handing an exception to another operator.
